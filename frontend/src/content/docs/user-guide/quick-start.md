### Reviewing an existing case

1. From the dashboard, search by project, family ID, or sample ID.
2. Open the family to land on its workspace.
3. Pick the analysis that matches the question — small variants, structural variants, repeats, and
   so on. Buttons appear only for data types the family actually has.
4. Build a candidate shortlist in the variant table before opening dense viewers.
5. Record interpretation as you go with classifications, tags, and notes.

### Setting up a new case

1. Confirm (or create) the target project and its assembly.
2. Build the family and samples in **Family Builder**, or bulk-import a prepared folder package via
   **Package Import** (admin).
3. Import or attach the assay layers for the family.
4. Open the family workspace to confirm the expected tables and tracks appear.

> **Not finding a variant you expect?** The most common causes are a frequency or quality filter
> that is too strict, or imputed calls being hidden. Clear filters and re-check scope before
> assuming the data is missing.
