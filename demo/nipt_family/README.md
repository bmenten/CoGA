# Synthetic monogenic NIPT demo family

A deterministic, ground-truthed dataset for validating the monogenic NIPT
analysis end to end — by the automated suite and by hand in the running app.
The data files are generated by `scripts/generate_nipt_demo.py`, and this README
is written by hand; regenerate the files if you change the scenario.

The fetal fraction is **12%** (FF/2 = 6%). The combined VCF carries variants
spanning all eight maternal/fetal categories plus a low-quality drop and a
recurrent-artifact candidate; each line records its ground-truth category in the
`EXP_CAT` INFO field, which the end-to-end test reads back.

## Files

| File | What |
| --- | --- |
| `nipt_combined.vcf` | One combined two-sample VCF: `FATHER_NIPT` (germline) + `CFDNA_NIPT` (maternal plasma). FORMAT `GT:DP:AD:AF`. |
| `nipt_coverage.bed` | cfDNA coverage over the family ROI (`1:1000-20000`): 80× with a 45× stretch. |
| `nipt_trio.ped` | The trio: father, mother (cfDNA), fetus (placeholder, no sequencing column). |
| `manifest.yaml` | Makes the folder a family package for Package Import: the analysis type, the cfDNA sample's assay and the datasets. |

## Ground truth (what the analysis should report)

**Fetal fraction:** ≈ **12.0%**, estimated from **40 category-7 sites**, high
confidence.

**Category counts** (after filtering):

| Cat | Meaning | Count | Example variant |
| --- | --- | --- | --- |
| 1 | de novo in fetus | 1 | `1-1001-A-G` (GENE_DENOVO) |
| 2 | maternal het, not inherited | 1 | `1-2001-A-G` |
| 3 | maternal het, inherited (het) | 1 | `1-3001-A-G` (GENE_RECESS) |
| 4 | maternal het, hom fetus | 1 | `1-4001-A-G` (GENE_HOMRISK) |
| 5 | maternal hom, het fetus | 1 | `1-5001-A-G` |
| 6 | maternal & fetal hom | 1 | `1-6001-A-G` (GENE_MATHOM2) |
| 7 | paternal, transmitted | 40 | `1-10000-A-G` … |
| 8 | paternal hom-alt, absent (FN) | 1 | `1-8001-A-G` |

**Filter funnel:** total **49** → quality-filtered **1** (`1-9001-A-G`,
GENE_LOWQUAL, cfDNA depth 5) → artifact-filtered **1** (`1-9501-A-G`,
GENE_ARTIFACT — *only once you add it to the artifact list*, see below) →
analysed **47**.

**Recessive at-risk** (inheritance preset `recessive_at_risk`) — the fetus is at
risk in:

- **GENE_RECESS** — compound heterozygote: a transmitted paternal allele
  (`1-10000-A-G`, cat 7) + a transmitted maternal allele (`1-3001-A-G`, cat 3).
- **GENE_HOMRISK** — homozygous (`1-4001-A-G`, cat 4).
- **GENE_MATHOM2** — homozygous (`1-6001-A-G`, cat 6).

GENE_CARRIER (`1-10010-A-G`, a lone paternal cat-7 hit) is **not** at risk.

**Other inheritance presets:** `de_novo` → `1-1001-A-G`; `paternal_dominant` →
the 40 cat-7 sites; `maternal_dominant` → `1-3001-A-G` (cat 3) and `1-4001-A-G`
(cat 4).

**On-target coverage** (no gene/panel filter → the family ROI): overall median
**80×**. (Per-gene coverage needs the genes in the reference table, so use the
ROI for the synthetic genes here.)

## Automated validation

`backend/tests/test_nipt_end_to_end.py` parses this VCF, runs the analysis core,
and asserts the fetal fraction, every category, the funnel, and the recessive
genes above:

```bash
backend/.venv/bin/python -m pytest backend/tests/test_nipt_end_to_end.py
```

## Loading it for hands-on testing

### Option A — Package Import (recommended)

`manifest.yaml` makes this folder a self-describing package: it declares
`analysis_type: monogenic_nipt`, tags `CFDNA_NIPT` with `assay: nipt_cfdna`, names
the PED, and lists the datasets — the combined father+cfDNA VCF (`snv`) and the
cfDNA `coverage` BED.

Package Import scans the folders in `FAMILY_IMPORT_ROOTS` (default `/data/families`).
In the Docker stack the repository's `data/` folder is mounted at `/data`, so copy
the package there:

```bash
mkdir -p data/families && cp -R demo/nipt_family data/families/
```

(With the backend running on your machine you can instead set `FAMILY_IMPORT_ROOTS`
to the repository's `demo/` folder.) Then, as an admin, open **Package Import**
(`/package-import`), pick **nipt_family · monogenic_nipt** in the **Family folder**
dropdown, and import. That's the whole demo in one step: the tagged NIPT trio, the
classified variants, and the on-target coverage. (No bgzip/index needed — the
family-VCF importer accepts the uncompressed `.vcf`.)

### Option B — Family Builder / API

1. **Create the NIPT trio.** In the **Family Builder** (`/family-builder`), tick
   **Monogenic NIPT**, add the father, the mother (sample `CFDNA_NIPT`, ticked
   **cfDNA (maternal plasma)**), and the fetus as the proband (parents
   FATHER_NIPT / CFDNA_NIPT). That posts the tagged family for you.

   Or via the API — `POST /api/ped/manual` with the family tagged
   `metadata.analysis_type = "monogenic_nipt"` and the cfDNA member tagged
   `metadata.assay = "nipt_cfdna"`:

   ```json
   {
     "family_id": "FAM_NIPT_DEMO",
     "metadata": {"analysis_type": "monogenic_nipt"},
     "members": [
       {"sample_id": "FATHER_NIPT", "sex": "male"},
       {"sample_id": "CFDNA_NIPT", "sex": "female", "metadata": {"assay": "nipt_cfdna"}},
       {"sample_id": "FETUS_NIPT", "sex": "und", "is_proband": true,
        "father_id": "FATHER_NIPT", "mother_id": "CFDNA_NIPT"}
     ]
   }
   ```

2. **Upload the combined VCF:** `POST /api/families/FAM_NIPT_DEMO/small-variants/upload`
   with `nipt_combined.vcf` (its two columns map to FATHER_NIPT and CFDNA_NIPT;
   the fetus has no column).

3. **Upload coverage:** `POST /api/bed/upload/CFDNA_NIPT/coverage` with
   `nipt_coverage.bed`, and set the family **ROI to `1:1000-20000`** (Family
   dashboard → ROI editor) so the coverage card has a target.

4. **Open the family** → the **Monogenic NIPT** tab shows the fetal fraction,
   the filter funnel, the category counts, on-target coverage, and the classified
   variant table. Try the inheritance presets above.

5. **Artifact filter (optional):** add `1-9501-A-G` to the artifact list via
   `POST /api/admin/nipt/artifacts` (`{"assembly_id": "<id>", "variant_id":
   "1-9501-A-G"}`) and reload — the funnel's "artifact-filtered" count becomes 1
   and that variant drops out. `POST /api/admin/nipt/artifacts/auto-seed` would seed
   recurrent variants automatically on a real cohort.
